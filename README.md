# LedgerCore

Учебный Go-сервис учета внутренних переводов в RUB: двойная запись, неизменяемый журнал, идемпотентность, защита от конкурентного списания и независимая сверка. Использует тестовые средства; банков и реального движения денег нет.

Суммы передаются строками в копейках, вычисляются проверенной целочисленной арифметикой и хранятся как BIGINT. Успешная операция атомарно фиксирует две проводки, оба остатка и результат идемпотентности. Отмена создает новую обратную операцию.

## Запуск

При работающем Docker Engine и Compose v2 после чистого checkout:

```sh
docker compose up --build -d
```

Команда поднимает PostgreSQL с отдельным постоянным томом, создает роли, применяет миграции и запускает API. Доступ: `http://127.0.0.1:8080`, health endpoints `/livez`, `/readyz`, метрики `http://127.0.0.1:9090/metrics`.

Для локального quick start Compose содержит явно демонстрационные учетные данные. Настройки перечислены в [.env.example](.env.example); необязательный `.env` позволяет их заменить. Образы закреплены tag + digest, версии Go и зависимостей зафиксированы. Секретов в образе нет; runtime работает под UID 65532. Публичные API требуют статический bearer token. Это один доверенный контур без разграничения доступа пользователей к кошелькам.

```sh
make demo       # тестовое финансирование, перевод, отмена, 16 параллельных повторов, сверка
make reconcile  # независимая сверка без исправления данных
make down       # остановка, данные сохраняются
```

`make up` эквивалентен команде запуска. При отсутствии Make вызывайте соответствующие команды из [Makefile](Makefile), например `docker compose --profile tools run --rm ledgerctl demo`. На этой Windows установлен `C:\msys64\ucrt64\bin\mingw32-make.exe`.

Повторный `make demo` возвращает сохраненные результаты: начальное финансирование не удваивается. Отдельная команда удаления данных — `make destroy-data`; обычный `down` том не удаляет.

**Проверено здесь:** нативный запуск на PostgreSQL 17.9, миграции на чистых БД, HTTP demo дважды, unit/integration `-race`, vet, Staticcheck, сборка и нагрузка. **NOT RUN:** сборка образа и запуск Compose — установленный Docker Desktop не смог запустить движок. Синтаксис всех Compose profiles проверен. Hosted CI и реальный Linux SIGTERM-прогон в этой сессии не запускались. Подробности и воспроизведение — в [отчете приемки](docs/acceptance.md).

## Проверки

Нужны Go 1.26.2 и C-компилятор для race detector; интеграционные проверки используют PostgreSQL, без SQL-моков.

```sh
make test
make test-integration
make lint
make build
make bench
make explain
```

`make test-integration` использует отдельную БД в tmpfs. Только там выполняются тестовые аварии и намеренная порча проекции. Для нативной БД настройте три `LEDGER_TEST_*` URL и `LEDGER_REQUIRE_INTEGRATION=1`, затем `make test-integration-local`. Имя тестовой БД должно содержать `test`. `go test ./...` без этих переменных явно пропускает интеграционные тесты; CI требует их выполнения.

В этой Windows для GCC потребовался ASCII-путь в `GOTMPDIR`, `TEMP`, `TMP`; команды приведены в [описании окружения](docs/environment-notes.md). Плавающие версии линтера и SQL-моки не используются.

## API

Полный контракт и семантика повторов: [OpenAPI](docs/openapi.yaml).

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/accounts` | Нулевой клиентский кошелек, тело `{"name":"Alice"}` |
| GET | `/v1/accounts/{id}` | Баланс и метаданные |
| POST | `/v1/transfers` | Перевод, обязателен `Idempotency-Key` |
| GET | `/v1/transfers/{id}` | Операция и две проводки |
| POST | `/v1/transfers/{id}/reversal` | Полная отмена, новый ключ |
| GET | `/v1/accounts/{id}/entries` | История, `limit=1..100`, `cursor` |
| GET | `/livez`, `/readyz` | Проверки без bearer token |

Пример тела перевода:

```json
{
  "from_account_id": "<UUID отправителя>",
  "to_account_id": "<UUID получателя>",
  "amount_minor": "2500",
  "currency": "RUB",
  "metadata": {"purpose": "demo"}
}
```

Каждый запрос `/v1` передает `Authorization: Bearer <API_TOKEN>`. Тело ограничено 32KiB, метаданные — 16 полей/2048 кодированных байт, страница — 100 записей. Ошибки имеют `error.code`, `error.message`, `request_id`. Инфраструктурный 503 требует повтора с тем же ключом: при потере соединения во время commit результат может быть неизвестен. Окончательный бизнес-отказ также сохраняется. Создание кошелька не идемпотентно.

Баланс читается в одном committed snapshot. История использует последовательность каждого счета и фиксирует верхнюю границу первой страницы; отдельные запросы баланса и истории могут относиться к разным моментам. Сверка читает всю БД в одном REPEATABLE READ READ ONLY snapshot.

## Компоненты и решения

| Каталог | Ответственность |
|---|---|
| `cmd/api` | Настройки, listeners, сигналы и ограниченный shutdown |
| `cmd/ledgerctl` | Миграции, fixtures, demo, reconcile, bench, explain |
| `internal/ledger` | Money, нормализация, fingerprint, модель переходов |
| `internal/store` | Явный SQL, порядок блокировок, идемпотентность и retry |
| `internal/httpapi`, `internal/observability` | HTTP и метрики |
| `internal/reconcile` | Независимые NUMERIC-агрегаты и проверка инвариантов |
| `migrations` | Встроенные миграции, checksum, deferred constraint triggers |
| `tests` | Реальная конкуренция PostgreSQL и тестовые аварии |

Основные документы: [инварианты](docs/invariants.md), [архитектура](docs/architecture.md), [четыре ADR](docs/adr-001-money-and-ledger.md), [demo и нативный запуск](docs/demo.md), [нагрузка и EXPLAIN](docs/benchmarks.md), [приемка, вопросы и резюме](docs/acceptance.md).

В локальном эксперименте на Ryzen 7 5800HS при 32 клиентах получено 344.27 запросов/с для общей пары и 2247.54 для независимых пар; по 1024 запроса на сценарий, без ошибок, сверка успешна. Это короткий прогон на общем Windows-хосте; исходные измерения, p50/p95/p99 и ограничения приведены в отчете нагрузки.
